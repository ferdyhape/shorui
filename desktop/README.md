# Shorui desktop

Installable desktop build of Shorui: a Tauri window around the same frontend/backend as the web
app, no internet, no server to reach by hand. Nothing in `backend/` or `frontend/` is duplicated
here - this directory only packages whatever is currently there.

**Development still happens in `backend/` and `frontend/` exactly as before** (`../dev.sh`). Only
once a feature is ready do you bring it into the desktop build, with the two commands below.

## One-time setup

- Rust (GNU toolchain) + a standalone MinGW-w64, both via winget:
  ```bash
  winget install --id Rustlang.Rustup -e
  rustup default stable-x86_64-pc-windows-gnu
  winget install --id BrechtSanders.WinLibs.POSIX.UCRT -e
  ```
  Add the WinLibs `mingw64\bin` folder (wherever winget installed it - check
  `%LOCALAPPDATA%\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.*\mingw64\bin`) to your `PATH`.
  Rust's own `rust-mingw` component (installed automatically with the toolchain above) ships a
  partial linker only - a full MinGW-w64 is still required for `dlltool`. This is the trade-off
  for the GNU route: lighter than MSVC's Visual Studio Build Tools (no multi-GB install), but a
  less common Windows Rust setup; if it ever becomes a maintenance burden, switch to
  `rustup default stable-x86_64-pc-windows-msvc` and install the "Desktop development with C++"
  workload instead - nothing else about this directory needs to change for that.
- `pyinstaller` in the backend venv (`backend/.venv/Scripts/python -m pip install pyinstaller`) -
  already added to `backend/requirements-dev.txt`.
- `npm install` in this directory (`@tauri-apps/cli` only).

## Commands

```bash
npm run dev     # preview the shell against the web dev server - start ../dev.sh first
npm run sync    # rebuild frontend (desktop tool set) + backend (PyInstaller) from current source
npm run build   # sync, then produce the installer (desktop/src-tauri/target/release/bundle/)
```

(Each is a thin wrapper around `scripts/dev.sh` / `scripts/sync.sh` / `scripts/build.sh`.)

## How it fits together

- **Fixed port, not dynamic.** The bundled backend always listens on `127.0.0.1:47821` (picked to
  avoid clashing with the web dev server's default `:8000`). The frontend's `api/client.ts` already
  reads its base URL from `VITE_API_BASE` with no change needed - `sync.sh` just bakes in
  `http://127.0.0.1:47821/api/v1` at build time. A dynamic port was deliberately skipped: this is a
  single-user local app, and a fixed port avoids a Rust<->webview port handshake for no real gain.
  The number is repeated in three places by necessity - `backend_entry.py`, `src/main.rs`, and
  `scripts/sync.sh` - all three must agree if it's ever changed.
- **Docx to PDF is excluded from this build** (needs LibreOffice installed separately, ~300-500MB,
  not worth bundling for one tool). This is one reversible flag, not a fork:
  `frontend/src/tools.ts`'s `desktop: false` on that tool, and `backend/app/main.py` skipping its
  router when the `SHORUI_DESKTOP=1` env var is set (set by `backend_entry.py`/`main.rs`, never set
  by the normal web `uvicorn app.main:app` entrypoint). Every other tool ships, unchanged.
- **CORS.** Tauri's bundled webview loads the frontend from its own internal origin
  (`tauri://localhost` / `https://tauri.localhost`), not `http://localhost:5173` like the Vite dev
  server - `main.rs` sets `SHORUI_CORS_ORIGINS` to those origins when spawning the backend;
  `core/config.py` already parses that env var as a JSON list, no backend code change needed.
- **Sample files.** Each tool's downloadable sample (`app/tools/<name>/samples/`) is plain data, not
  Python code, so PyInstaller won't find it on its own - `sync.sh` has one `--add-data` per tool
  that has a samples dir. Adding a new tool with its own sample must add a line there too, or that
  tool's sample download 500s in the desktop build only (web is unaffected either way).
- **`dist-frontend/` and `binaries/`** are build output, gitignored, regenerated by `sync.sh` every
  time - never edit anything there by hand.

## Verifying a build works

```bash
# backend alone, no Tauri involved - confirms PyInstaller's output is truly self-contained
./src-tauri/binaries/backend/shorui-backend.exe &
curl http://127.0.0.1:47821/api/health
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1:47821/api/v1/pdf-tools/samples/sample-a.pdf
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1:47821/api/v1/docx-to-pdf/samples/sample.docx  # 404 - excluded
```

Then `npm run build` and install/run the produced `.exe`/`.msi` to confirm the full shell.
